# SEO audit, 2026-09-24

Scope: everything in the repo that affects how search engines crawl, index, and display cerulean.news. No Search Console or other account work. Analytics (GA4 `G-X1CZ0X5LMG`) and the crawler's politeness, user agent, and network settings were left alone.

## What is generated and what is hand-written

`site/index.html`, `site/trends.html`, and `site/site.webmanifest` are hand-written; nothing in `src/` writes them. `src/outputs.js` generates `feed.rss`, `feed.json`, and `feed-audit.json`. The committed `site/feed.json` still says `"title": "Blue News"` (`site/feed.json:3`), but it is a June build artefact that never reaches production: full runs regenerate it, and static-only runs replace it with the live copy before deploy (`.github/workflows/publish-feed.yml`, "Reuse live feed for static deploy"). The generator already says "Cerulean News" (`src/outputs.js`, `buildRss` and `buildJsonSummary`), and the live feed agrees:

```
$ curl -s https://cerulean.news/feed.json | jq -r .title
Cerulean News
```

A new test fails if "Blue News" returns to the generator or the pages.

## Findings and changes

### 1. robots.txt and sitemap.xml did not exist

Evidence: both returned the homepage.

```
$ curl -sI https://cerulean.news/robots.txt
HTTP/2 200
content-type: text/html; charset=utf-8
$ curl -sI https://cerulean.news/sitemap.xml
HTTP/2 200
content-type: text/html; charset=utf-8
```

Changed: added `site/robots.txt` (allow all, `Sitemap:` line) and `site/sitemap.xml` listing `https://cerulean.news/` and `https://cerulean.news/trends`. No `lastmod`, because the page content changes with every build and a static date would be wrong within the hour.

### 2. Every unknown path was a soft 404

Evidence: `curl -sI https://cerulean.news/nonexistent-page` returned `HTTP/2 200` with the homepage. Cloudflare's docs say that without a top-level `404.html`, Pages assumes a single-page app and serves the root for every unmatched path (developers.cloudflare.com/pages/configuration/serving-pages, "Single-page application (SPA) rendering"). Search engines see this as an unlimited set of duplicate homepages.

Changed: added `site/404.html` with `noindex` and links to the reader, trends, and feeds. The reader uses `#page=` hashes, not paths, so no route depended on the fallback. The zone-level shortcuts (`/sentiment`, `/rss`, `/json`, `/trends/`) are Cloudflare redirect rules and fire before Pages, so they are unaffected.

### 3. The pages.dev hostname served a second indexable copy

Evidence: `curl -sI https://bluenews-7g0.pages.dev/trends` returned `HTTP/2 200` with no `X-Robots-Tag`. The canonical tags point at cerulean.news, which helps, but a canonical is a hint.

Changed: added `site/_headers` with `X-Robots-Tag: noindex` for `https://:project.pages.dev/*` and `https://:version.:project.pages.dev/*`, the pattern Cloudflare documents for this (developers.cloudflare.com/pages/configuration/headers, "Prevent your pages.dev URLs showing in search results"). The workflow's curl seed from `bluenews-7g0.pages.dev` ignores the header. A test forbids a bare `/*` noindex rule, which would deindex the real domain.

### 4. feed-audit.json is public and crawlable

Evidence: `curl -so /dev/null -w "%{http_code} %{size_download}" https://cerulean.news/feed-audit.json` gave `200 10085303`. It holds rejected items and crawl state.

Changed: `X-Robots-Tag: noindex` for `/feed-audit.json` in `site/_headers`. Not blocked in robots.txt, since a disallowed URL can still be indexed from links and the crawler would never see the noindex.

### 5. Canonical URLs are the extensionless ones; internal links were not

Evidence:

```
$ curl -sI https://cerulean.news/index.html   ->  HTTP/2 308, location: /
$ curl -sI https://cerulean.news/trends.html  ->  HTTP/2 308, location: /trends
$ curl -sI https://www.cerulean.news/         ->  HTTP/2 301, location: https://cerulean.news/
$ curl -sI http://cerulean.news/              ->  301, location: https://cerulean.news/
$ curl -sI https://bluenews.online/           ->  HTTP/2 301, location: https://cerulean.news/
```

The canonical tags were already right (`https://cerulean.news/` and `https://cerulean.news/trends`). But the homepage linked to `trends.html` twice (topbar and footer), so every internal link went through a 308.

Changed: both links now use `trends`. A test forbids `index.html` or `trends.html` hrefs in either page.

### 6. Feeds linked to a non-canonical homepage URL

Evidence: the RSS `<link>` and JSON `home_page_url` were `SITE_URL` verbatim, `https://cerulean.news` without the slash the canonical tag uses (`src/outputs.js`, `buildRss` and `buildJsonSummary`).

Changed: new `siteHomeUrl()` in `src/outputs.js:63` normalizes to one trailing slash; both feeds use it (`src/outputs.js:239`, `src/outputs.js:302`). The JSON Feed also gains the 1.1 `icon` (icon-512.png), `favicon` (favicon-32x32.png), and `language` fields, emitted only when the site URL is known.

### 7. Meta descriptions were too long

Evidence: the homepage description was 250 characters and the trends one 185; Google cuts snippets at roughly 155 to 160.

Changed: 162 and 145 characters, still ending with "Not affiliated with any insurer." The same text is used for `og:description`, `twitter:description`, and the JSON-LD `description`. A test caps length at 165 and requires the disclaimer.

### 8. Structured data named the site with its tagline

Evidence: the homepage `WebSite.name` was "Cerulean News: Vermont health care and health insurance news". Google uses `WebSite.name` for the site name shown in results, which should be the bare brand.

Changed: `name` is "Cerulean News", the full title moved to `alternateName`, and the node gets `@id` `https://cerulean.news/#website` and `inLanguage`. The trends `WebPage` gets an `@id`, `inLanguage`, and `isPartOf` pointing at that `WebSite`. Both blocks still parse as JSON (tested).

### 9. Trends page had no feed discovery links

Evidence: `site/trends.html` had no `<link rel="alternate">` for RSS or JSON; only the homepage did.

Changed: added both, matching the homepage.

### 10. Social preview metadata was thin

Evidence: `og:image` is the 512 by 512 icon with no size, type, or alt (`site/index.html:24`).

Changed: added `og:image:type`, `og:image:width`, `og:image:height`, `og:image:alt`, and `og:locale` on both pages. The `summary` Twitter card fits a square image, so it stays.

### 11. Stated refresh cadence was wrong

Evidence: the footer said "Refreshed every four hours" and "Every few hours it collects", and the dateline fallback said "Updated every four hours", but the workflow cron is `17,47 * * * *`.

Changed: all three now say about every 30 minutes. `README.md:154` and `README.md:407` still say four hours; I left the README alone since it is not served.

## Checked and left as is

- **Titles.** Both are unique and under 60 characters. No change.
- **Headings.** One `h1` per page; stories render as `h2` (`site/index.html`, `createElement("h2")`). Trends charts use `figure` and `figcaption` with `role="img"` SVGs described by hidden text, and a data table with `scope` headers. Fine.
- **Images and alt text.** The pages have no `<img>` elements; icons are `link` tags, and the decorative tricolor bar is `aria-hidden`. Nothing to fix.
- **Render-blocking resources.** CSS and JS are inline; the only external script is gtag with `async`. The HTML is 9.8 KB over brotli.
- **Caching headers.** Pages defaults are `max-age=0, must-revalidate` for HTML and feeds and `max-age=14400` for icons, with ETags. Cloudflare recommends against custom caching on Pages, and the icons are not fingerprinted, so longer lifetimes would strand stale copies. No change.
- **`meta name="keywords"`.** Google ignores it; harmless, so left in place.
- **Alert text.** `src/alerts.js:85` still says "Blue Cross VT News Mention Monitor Alert". It goes to Slack and Discord only, never to the site, so it is out of scope here.

## Left for Oliver

1. **Search Console and Bing Webmaster Tools.** Verify `cerulean.news` as a domain property, submit `https://cerulean.news/sitemap.xml`, and after the next deploy use URL Inspection on `/` and `/trends` to confirm the rendered HTML includes stories. Check the Pages report for `bluenews-7g0.pages.dev` URLs or soft 404s from before this change; they should drop out.
2. **Post-deploy check.** After the next deploy:
   `curl -sI https://cerulean.news/robots.txt` should show `content-type: text/plain`, `curl -sI https://cerulean.news/nope` should show `HTTP/2 404`, and `curl -sI https://bluenews-7g0.pages.dev/` should show `x-robots-tag: noindex`.
3. **`/trends/` redirect is a 302.** `curl -sI https://cerulean.news/trends/` returns `302` to `/trends`. It comes from the zone's dynamic redirect rules, not the repo; changing it to 301 in the Cloudflare dashboard would pass the signal permanently. The `/sentiment`, `/rss`, and `/json` shortcuts can stay 302.
4. **Stories are rendered by JavaScript from a large feed.** The homepage HTML contains only "Loading stories…"; the headlines come from `fetch("feed.json")` (`site/index.html:1192`, `site/trends.html:1684`). The live feed is 4.37 MB raw and 605 KB over brotli for 1,869 items, and `id`, `guid`, `url`, and `link` repeat the same URL in every item. Google renders JavaScript, so this is indexable, but it slows first paint and makes indexing depend on rendering. Two options, both larger than this pass: have the generator also write a small paged or recent-only JSON for the reader, or prerender the newest headlines into the HTML at build time. I did not do either (see below).
5. **Share image.** `og:image` is the square icon. A 1200 by 630 image with the name and tagline would give a larger preview on social sites (then switch `twitter:card` to `summary_large_image`).
6. **README cadence.** `README.md:154` and `README.md:407` still say every four hours.

## Not changed, and why

- **Prerendering stories or slimming feed.json.** Prerendering would make `index.html` a build output, but static-only deploys ship the committed file, so the snapshot would go stale and the hand-edited page would start fighting the generator. Dropping duplicate fields from `feed.json` would break other readers of a public JSON Feed. Both need a decision from Oliver.
- **Regenerating the committed `site/feed.json` and `feed.rss`.** They are build artefacts replaced on every deploy; hand-editing them would mislead the next reader of the repo. They need a full generator run (network access and Gemini keys) to refresh properly.
- **Disallowing feed-audit.json in robots.txt.** A disallow hides the noindex header from crawlers; the header alone is the right tool.
- **Custom cache lifetimes.** See "Caching headers" above.
